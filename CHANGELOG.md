# Changelog

All notable changes to this project will be documented in this file.

## v0.4.0

The check plan now audits every certificate the CA has issued, from the CA's signed directory, so
the fleet's expiry is visible from the CA host without an inventory. By default only the due and
expired ones are listed and a summary line counts the whole directory; `issued=all` lists every
one, `issued=none` skips the directory. Certificates still on disk but revoked in the CRL are
marked. Issued certificates never change the CA's own status, so the extend plan's nothing-due
guard is unaffected.

The `extend_ca` task now probes for the `puppetserver ca extend` subcommand proposed in
openvoxserver-ca#56 and prefers it when present, with the module's own implementation as the
fallback; `implementation=library` or `implementation=gem` forces one or the other. The wrapper
takes its own backups and verifies that every certificate kept its serial and key and moved its
expiry. Exercised only against a stand-in in the unit tests until the subcommand ships.

Also: a `REFERENCE.md` generated by puppet-strings, a README section on managing the agents'
CA copy from a manifest, the overview rewritten in the present tense, and the five-year `ca_ttl`
default for a server-generated CA noted alongside the fifteen years `puppetserver ca setup`
gives. Lab battery case CHK-06 covers the audit.

## v0.3.1

The check tasks now fail with `openvox_ca/missing-files` when the certificate files are absent,
which is what a non-root run looks like, instead of reporting `ok` with nothing in it. Found by the
new lab battery under `contrib/`, which runs 30 positive and negative cases against a disposable
lab and passes in full.

## v0.3.0

The `openvox_ca::distribute` plan with the `read_ca_bundle`, `upload_ca`, and `remove_localcacert`
tasks. `refetch` is the default strategy; `upload` is for hosts that cannot reach the server. Lab-verified
against agents whose CA copy had already expired.

## v0.2.0

The `openvox_ca::extend` plan with the `extend_ca`, `regen_primary_cert`, and `refresh_puppetdb_ssl`
tasks. Verified on the lab: single-layout CA extended to 15 years, server certificate regenerated with
alt names and the CA CLI extension, OpenVoxDB refreshed, agents ran clean afterwards.

## v0.1.0

Read-only checks: the `openvox_ca::check` plan with the `check_ca` and `check_host_cert` tasks.
Verified against a three-node OpenVox 8 lab.

## v0.0.1

Repository skeleton only: scaffold, CI, and release workflow. No plans or tasks yet.
